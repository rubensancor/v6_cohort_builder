pc-cohort-builder · vantage6 5.0 algorithm · v6 tooling

From cohort definition
to federated patient counts.

The algorithm accepts either OHDSI CohortGenerator SQL or an ATLAS cohort expression, sends one cohort job to every organization, builds the cohort inside each node's OMOP database, and returns exact subject counts to the central task.

The production cohort path is central.py → federated.py → cohort.py. extract.py and preprocess.py are still template examples and are not used by this flow.

File map

How the Python scripts fit together

__init__.pyexports

Wrapper-visible package surface

Imports and exposes central_function and generate_cohort_count so the vantage6 algorithm wrapper can resolve both method names from the package root.

Calls: none · Used by: algorithm wrapper and import tests
central.pyorchestrator

Coordinates the federated job

  • Validates the input through cohort.py.
  • Converts ATLAS JSON into CohortGenerator SQL.
  • Lists organizations and creates generate_cohort_count subtasks.
  • Waits for results and aggregates them.
Boundary: owns orchestration, never opens an OMOP connection.
federated.pynode action

Adapts node execution into a stable payload

Reads the OMOP environment, calls execute_cohort_generation(), adds organization/node identity, and converts every exception into a structured status: error response.

Boundary: the error containment layer around database execution.

Contains the reusable rules and the real cohort operation

Node executionparse_omop_configexecute_cohort_generationextract_subject_count
Central resultaggregate_central_resultsgenerate_cohort_id

The real write path creates cohort tables, checks existing rows, optionally deletes them, passes a one-row definition set through the Python-to-R bridge, generates the cohort, obtains counts, and always disconnects.

local-omop/smoke_federated.pyreal smoke

Exercises one real federated node locally

Sets safe defaults, loads the sample SQL, calls _run_generate_cohort_count() with overwrite enabled, prints JSON, and exits non-zero on node failure or count mismatch.

It bypasses: central.py and a live vantage6 network.

Demonstrates task creation in a mock network

Creates three mock organizations and submits central/federated methods. It is an executable demonstration, not a collected pytest case, and its dataframe datasets do not replace the OMOP configuration required by the real node path.

06

Behavioral contracts

Success and failure are deliberate

A

One input format

Both SQL and ATLAS JSON is ambiguous; neither is unusable. The central helper rejects both cases.

B

Same cohort ID everywhere

The central request generates or accepts one positive ID and forwards it to every organization.

C

No silent overwrite

Existing rows cause a node error unless overwrite=True; overwrite deletes matching rows first.

D

Errors stay attributable

The node response includes organization/node identity when configuration was parsed before the failure.

E

No misleading total

If a node errors or returns nothing, successful node counts remain visible but total_count becomes null.

F

OHDSI count compatibility

The parser recognizes several count shapes, including the real cohortId + cohortSubjects output.
